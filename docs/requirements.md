# 需求说明书

## 目标与用户

CampusLink 面向校园学生，为校园拼车、校园悬赏、二手书提供统一入口。系统由公共基础和三个业务模块组成。公共基础统一提供身份认证、资料、图片上传和页面布局；三个模块围绕各自校园场景独立设计，并集成为同一应用。本文描述全系统需求，公共需求与三个业务模块需求见下文。

访客可浏览首页和模块入口；注册用户可维护自己的资料并访问“我的内容”。当前不设置管理员或其他角色。

## 公共基础需求

| 编号 | 需求 | 完成判定 |
| --- | --- | --- |
| F01 | 注册 | 用户名唯一；成功进入登录页并预填用户名，不自动登录 |
| F02 | 登录与退出 | 正确凭据可登录；退出清除本地状态；刷新能恢复有效身份 |
| F03 | 页面权限 | 首页与模块首页公开；个人中心及我的内容需登录，登录后返回原页面 |
| F04 | 用户资料 | 展示用户名、昵称、头像；可修改昵称和头像，不能修改用户名 |
| F05 | 图片上传 | 登录后上传 JPEG、PNG、WebP，最大 5 MiB，校验实际内容并返回 URL |
| F06 | 公共页面 | 首页、导航、登录注册、个人中心、404；手机可展开导航 |
| F07 | 模块开发空间 | Ride、Quest、Book 有独立目录、公开页、个人页和空 Router |
| F08 | 环境连通 | 健康检查真实访问数据库；可用返回 200，不可用返回 503 |

用户名限定 3–32 位英文字母、数字或下划线，存储前转小写；密码 8–128 字符；昵称去首尾空格后为 1–32 字符，注册未填写时默认用户名。表单错误应明确提示，提交期间避免重复提交。

## 公共约束

- 使用既定 Vue 3 / FastAPI / MySQL 技术栈，依赖版本固定；不使用 Docker。
- 所有业务接口沿用统一响应、身份依赖和数据库会话。业务数据不放入公共认证 Store。
- 密码只存 Argon2 哈希，JWT 密钥由环境配置；用户响应不含密码哈希。
- 页面统一绿色主题、公共容器和组件，适配桌面与手机。
- 数据库初始化不得删除已有数据，真实凭据和上传文件不提交仓库。

## 当前实现状态与范围边界

三个业务模块均已提供业务代码。悬赏复用公共账号与布局，支持一人接单及双向完成确认。系统不实现聊天、线上支付、积分、评价、后台管理或第三方登录；地图只用于校园拼车。

公共框架的完成判定以实际走通“注册→登录→模块入口→修改资料与头像→刷新→退出→重新登录”为准，并执行前端类型及构建检查。这不构成全组项目的最终验收；最终部署环境及必要的非功能要求由小组确认。

## 业务功能需求

### 校园拼车

支持发布、路线与日期筛选、详情、直接加入、退出、取消、完成和我的行程。每账号占一个名额，招募 1–6 人（不含发起人）；只有本人发布、未出发且无人加入的行程可编辑。出发时间限制未来 90 天，费用线下协商。联系方式仅向发起人及有效参与者按角色开放。

出发地、目的地、集合地点可手动输入，也可通过可选高德地图搜索、选点和主动定位。未配置或服务失败时保留手动填写。详细规则及验收清单见 [拼车计划](ride-plan.md)。

### 校园悬赏

面向跑腿代办、学习互助、维修帮忙和其他互助。支持公开浏览、关键词与分类/状态筛选、赏金或截止时间排序、分页、发布、编辑、单人接单、撤回接单、提交完成、发布者确认、取消与我的悬赏。赏金为 0–9999.99 元，最多两位小数，截止时间需为未来 30 天内。只有发布者可编辑未过期且无人接单的任务；接单者可在提交前撤回，撤回清除接单关系与联系方式。发布者只能取消无人接单的任务。超过截止时间的未接单任务不可接取；已接单任务允许继续交付和确认。联系方式和完成说明仅向发布者、当前接单者开放，赏金线下结算。详细字段、状态和验收条件见 [悬赏模块设计说明](quest-plan.md)。

### 二手书

支持发布、分类/成色/价格/交易方式筛选、详情、收藏、联系卖家、编辑、预定、取消预定、标记售出、下架和我的书籍。书籍信息含书名、作者、ISBN（选填）、分类（教材/教辅/考试资料/文学读物/其他）、成色（全新/几乎全新/轻微使用痕迹/明显使用痕迹）、1–6 张图片、现价与可选原价、是否可议价、交易方式（当面交易/校内代送/均可协商）及交易地点。只有本人发布且仍为在售状态的书籍可编辑；已预定、已售出、已下架后不可编辑。联系方式仅在书籍在售或已预定时向非发布者开放，发布者本人始终可查看用于核对与编辑回显。详细规则及验收清单见 [二手书模块设计说明](book-plan.md)。

## 系统验收要求

公共功能按前述要求检查。三个业务模块完成后，结合各自的功能要求检查完整操作流程，并验证共用账号、页面跳转和操作权限。具体业务验收条件随需求补充。
